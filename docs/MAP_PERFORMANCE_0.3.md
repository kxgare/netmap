# Замеры карты 0.2 → 0.3

Одна Linux-машина, Python 3.12.14, PySide6 6.10.2 / QtWebEngine, offscreen software rendering, viewport 1100×700, zoom=2, offline без тайлов и исходных линий. База сравнения — ресурсы карты commit 6ed06f1. Новый код — ветка netmap-0.3. Сеансы запускались последовательно без параллельных smoke-проверок.

scripts/map_benchmark.py создаёт в изолированном профиле 50/200/500/1000 уникальных тестовых IP с детерминированными координатами. Для каждого набора вызывается draw() 21 раз: первый записан отдельно, следующие 20 — медиана и P95. Центр и масштаб одинаковы, число объектов одинаковое: 50/166/247/350. Измеряется синхронный JS draw, не FPS и не весь путь Qt→WebChannel→GPU.

| Уникальных IP | Повторное обновление 0.2, мс | 0.3, мс | P95 0.2 / 0.3, мс | Первое обновление 0.2 / 0.3, мс |
|---:|---:|---:|---:|---:|
| 50 | 0.20 | 0.10 | 0.30 / 0.20 | 6.10 / 21.90 |
| 200 | 0.60 | 0.20 | 0.90 / 0.30 | 12.40 / 9.90 |
| 500 | 1.10 | 0.30 | 1.50 / 0.60 | 11.80 / 17.10 |
| 1000 | 2.20 | 0.70 | 2.80 / 0.90 | 17.00 / 27.70 |

Главное улучшение относится к повторной передаче той же геометрии: кэш кластеров и пропуск отрисовки сохраняют объекты и обновляют ссылки на текущие данные. Карточки с изменившимися timestamps/портами получают новые данные при открытии; открытая карточка обновляется только при изменении текста. Медиана 1000 IP снизилась с 2.20 до 0.70 мс (около 68%). Это конкретный сценарий, а не общий коэффициент ускорения.

Первое создание объектов в этом запуске медленнее, особенно на 50 IP; оно включает более подробные иконки и tooltip. По одному cold sample нельзя утверждать ускорение начальной загрузки. Дополнительные эффекты сглаживания обеспечиваются очередью 250 мс, debounce 80 мс, requestAnimationFrame и отсутствием тяжёлого draw во время drag; функциональный тест проверяет отложенное обновление.

[Исходный 0.2 JSON](performance/map-0.2.json), [0.3 JSON](performance/map-0.3.json), [отдельная плотность](performance/density-0.3.json). Замеры плотности тоже повторяют неизменный набор и используют кэш; они не измеряют полный redraw после pan/zoom. Значения около 0 мс ограничены разрешением таймера Chromium.

В настройках карты «Показывать время обновления карты» включает время draw в счётчике. В JS window.mapPerformance доступны draw_ms, cluster_ms, density_ms, updates и deferred; cluster_ms=0 при пропуске кластеризации. Отдельная воспроизводимая диагностика:

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python scripts/map_benchmark.py
NETMAP_BENCHMARK_DENSITY=1 QT_QPA_PLATFORM=offscreen .venv/bin/python scripts/map_benchmark.py
```

Для старой карты распакуйте git archive 6ed06f1 netmap/resources/map в отдельную временную папку и задайте NETMAP_BENCHMARK_MAP абсолютным путём к её netmap/resources/map. Рабочие файлы не заменяются. На Windows используйте .venv\Scripts\python.exe и задайте переменные через $env:NAME. Для окончательной оценки плавности нужны Windows 10/11, физический дисплей, drag/zoom, профиль Chromium frame timings и нагрузка реальными адресами с законной MMDB.
